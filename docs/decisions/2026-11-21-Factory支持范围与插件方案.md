# Factory 支持范围与插件方案

状态：已确认（Paseo Q1）

固定两名的适配范围已由[通用 MCP 名称适配](2026-11-23-通用MCP名称适配.md)替换。

用户的重放证据表明拒绝随工具名称变化。Factory 是否将原请求误判、是否支持该 Claude Code 接入方式、能否由上游修复，目前缺乏直接证据。依据见 [调研快照](../research/2026-11-21-上游项目与Hook核对.md)。

| 路径 | 影响 |
|---|---|
| 保留原调用链（已选） | 用户确认直接使用 Magpie Gateway Middleware 推进，按当前固定工具名边界验收 |
| Droid 原生 MCP | 保留 Factory 与 Paseo，改由 Droid 运行工具。需要另行确认 Paseo 的连接和认证方式，验收改为 Droid 会话 |
| 本地模拟验证骨架 | 先验证 Magpie 加载、路由、SSE 和非流式 Hook，能减少运行时不确定性。原目标的在线闭环仍需 Factory 确认 |

采用独立、无运行依赖的单文件 Gateway Middleware，以 model-map 为清单与测试布局参考。Node.js 22 和 npm 提供本地测试及打包工具，业务模块在 Magpie 的 moejs 中运行。先核对按 Provider 隔离的结构化变换与流式错误透传，再验证 Magpie 实际加载和两轮调用。真实 Factory 环境能否验收取决于可控的 Magpie 部署及 Factory 登录状态。

公开资料未确认 Factory 对该链路的支持。测试若显示名称适配无法在目标环境工作，记录错误及限制。实施固定映射一次并透传错误。
